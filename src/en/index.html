Main project

ATLAS — intelligent personal assistant

Under active development

The problem

A student juggles a class schedule, email, coursework, transit and fitness tracking across tools that don't talk to each other. ATLAS connects them in one agent that runs locally first and stays under my control.

The goal

A reliable, testable core where integrations plug in one at a time, with explicit rules about what the assistant is allowed to do on its own.

Technologies

  • Python 3.11+
  • SQLite
  • Daemon & scheduled tasks
  • Private HTTP API
  • pytest · ruff · mypy
  • ≈ 20,600lines of Python
  • 25modules
  • ≈ 1,500tests written

Overall architecture

Actual command-line output

Features actually implemented

  • Core pipeline: request → intent → context → plan → policy → execution → audit → response, with an audit log.
  • Policy engine: autonomy levels; sensitive actions don't run without approval.
  • Task engine: picks up where it left off after a restart, idempotent, with a capped number of retries.
  • University calendar: my class schedule (from ADE, the university's scheduling system) synced to a personal calendar, with configurable rules; exams take priority over regular classes.
  • Email: Gmail reading, deterministic extraction, a review queue for anything ambiguous.
  • Transit: train timetables (GTFS) tied to my schedule.
  • Fitness: imports workouts and recovery data from the Suunto API.
  • Studies: lectures, exercise sessions and labs turned into structured notes and review flashcards.
  • Private API and mobile page, reachable only over a private network and with a token.

Not done yet

Writing to Google Calendar (code ready, not enabled), voice commands, and several tool adapters that are only skeletons. Plugging in a local AI model is a goal, not something ATLAS does today. ATLAS has no consumer-facing interface: it's a personal tool, not a finished product.

Games and apps

Investors

Version 0.1 (release candidate)

A 3D economic management game that runs offline: you start with 15,000 CR, buy and upgrade businesses, invest in real estate, take out loans and trade on simulated markets until you own the whole city. No real transactions.

  • 20 businesses and 125 upgrades, 14 properties, a bank, and simulated markets.
  • A 3D city of 38 lots, with CC0-licensed (public domain) models and textures.
  • Frame rate measured on my laptop: 26 to 49 frames per second depending on the quality setting.

Limits: Windows version untested; audio not checked by ear during testing.

  • Python
  • Ursina / Panda3D

SILLON

Playable prototype

A native Linux 3D game where you program a drone on a farm. The player writes real OCaml, queries the game state in SQL and analyzes it in R: these are real tools, run in isolated processes, fully offline.

  • Three missions, with save and load.
  • An end-to-end test suite that measures memory use (roughly 50 to 70 MB seen in the screenshots).
  • Preceded by a web version with 183 learning missions.

Limits: Linux only; there is no Windows version.

  • Godot 4
  • C#
  • OCaml
  • SQLite · R

My current machine

My ASUS Vivobook F515EA is my only computer, used for my studies, my development and all of my projects. It's enough to code, test and keep making progress, but it holds me back as soon as several tools or large models come into play.

Studies, development and personal projects only

What works

  • Writing, testing and debugging ATLAS (≈ 1,500 tests written).
  • A MySQL server in a container for sql-exercism.
  • Godot 4 with SILLON, roughly 50 to 60 FPS in the screenshots.
  • Developing lightweight 3D games (Investors, SILLON).

Where it struggles

  • Local AI

    A 7-billion-parameter model, quantized, already takes about 4 to 5 GB: nearly everything left once the OS and editor are loaded. Generation on the CPU is slow, and larger models, fine-tuning or large search indexes are out of reach. (General rules of thumb, not my own measurements.)

  • Running out of RAM

    With a browser, an editor and containers open, my own system audits show memory almost full and swap almost exhausted during normal use.

  • Several tools at once

    Compiling, running tests, a Docker container, a game engine and an Android emulator (several GB on its own) don't coexist: I close and reopen things, and each experiment takes longer.

  • Integrated graphics

    My 3D game Investors runs at 26 FPS on high quality and 49 on low, with the laptop already under load. That's fine for a prototype, too tight for rendering or GPU-accelerated AI experiments.

Frame-rate measurements: laptop under load from an editor and an open game session, so on the pessimistic side; no measurement on a fresh boot with all 8 GB free.
